# Moving MySQL from Docker to Windows MySQL Server

The project currently uses the Docker MySQL container. These scripts move the
current database contents to a new `smart_ecommerce` database on Windows MySQL
without overwriting an existing Windows database.

## Prerequisites

- Docker Desktop is running and the current application works.
- Windows MySQL Server 8.0 is running on port `3306`.
- `mysql.exe` is installed. If it is not on your PATH, use:
  `C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe`.
- The existing Windows MySQL login has `CREATE DATABASE` permission and full
  permissions on the new `smart_ecommerce` database.

## 1. Export the current Docker database

From the project root in PowerShell:

```powershell
.\database\export_docker_mysql.ps1
```

Enter the existing application `DB_PASSWORD` value from the root `.env` file when prompted. The script writes a dated
SQL dump under `backups\`. Do not edit this file.

## 2. Import into Windows MySQL Server

Use your existing Windows MySQL username. Replace `your_windows_user` below:

```powershell
.\database\import_windows_mysql.ps1 `
  -DumpPath .\backups\smart_ecommerce-docker-export-YYYYMMDD-HHMMSS.sql `
  -Username your_windows_user
```

The script stops if `smart_ecommerce` already exists. It never deletes or
replaces an existing Windows database.

## 3. Verify with MySQL Workbench

Connect Workbench to Windows MySQL on `localhost:3306`, refresh schemas, and
open `smart_ecommerce`. Confirm `users`, `products`, `orders`, `payments`, and
`django_migrations` exist.

## 4. Switch Docker applications to Windows MySQL

Only after import verification, edit the root `.env`:

```env
DB_HOST=host.docker.internal
DB_PORT=3306
DB_USER=your_windows_user
DB_PASSWORD=your_windows_mysql_password
DB_NAME=smart_ecommerce
DATABASE_URL=
```

`DATABASE_URL` must be blank or removed because FastAPI otherwise uses its old
Docker-MySQL connection string. Do not commit `.env`.

Then recreate the database-using containers:

```powershell
docker compose up -d --force-recreate django celery celery-beat fastapi frontend
```

Docker MySQL may remain running temporarily as a rollback source. The services
will use Windows MySQL because `DB_HOST` is now `host.docker.internal`.

## 5. Validate the switched application

- Storefront: `http://localhost:5173`
- FastAPI health: `http://localhost:8000/health`
- Django Admin: `http://localhost:8001/admin/`
- MySQL Workbench: confirm application changes appear in Windows MySQL.

## Rollback

Change `.env` back to:

```env
DB_HOST=mysql
DB_PORT=3306
DATABASE_URL=mysql+pymysql://...@mysql:3306/smart_ecommerce
```

Then recreate the same services. Do not delete the Docker MySQL volume until
you have completed validation.
